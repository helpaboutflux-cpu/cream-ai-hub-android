최근 작업 기록

저장 공간이 부족하면 무슨 일이 생기나요

브라우저는 오리진(사이트)마다 저장 공간을 나눠 줍니다. LocalStorage 는 약 5MB(문자 기준)로 작고, IndexedDB 는 훨씬 큰 쿼터를 받습니다. 한도에 닿으면 setItem 이 QuotaExceededError 를 던지고 저장이 통째로 실패합니다. Lemon soft 공통 런타임은 이때 기존 데이터를 절대 잘라내지 않고, 화면 위에 경고 배너와 함께 이 페이지로 오는 버튼을 띄웁니다. 반대로 IndexedDB 는 넉넉해서 이 페이지에서도 용량 경고나 한도를 두지 않고, 지금 사용량과 항목 수만 보여줍니다.

안전하게 정리하는 순서

1

먼저 백업

백업 · 복원 화면에서 JSON 파일을 내려받아 둡니다. 되돌릴 수 있으면 지우는 일이 가벼워집니다.

2

용량 큰 항목부터 확인

데이터 정리 화면에서 용량 큰 순으로 정렬하고, 미리보기로 어떤 내용인지 확인합니다.

3

선택 → 확인 → 삭제

한 번에 하나씩 지워지지 않습니다. 선택한 항목과 총 용량을 확인 창에서 다시 보고 삭제합니다.

4

다시 진단

상단 새로고침으로 용량이 실제로 줄었는지 확인합니다. 줄지 않았다면 다른 키가 원인입니다.

서비스별 저장 위치

서비스 키 저장소

키 이름은 서비스별로 고정된 접두사를 씁니다. 목록에 없는 키는 기타로 묶여 표시됩니다.

용량을 줄이는 요령

  • -오래된 자동 저장 기록(lemon_autosave_*)은 지워도 현재 작업 화면만 다시 저장하면 됩니다.
  • -IndexedDB 사진은 한 장이 수백 KB 입니다. 참조되지 않는(고아) 미디어부터 정리하세요.
  • -내보내기 기록처럼 통계만 남기고 싶은 항목은 작은 값으로 다시 저장해도 됩니다.
  • -테마 설정값(cream_theme)은 몇 바이트라 정리 대상이 아닙니다.
